# Contributing

1. Open an issue describing the experiment or runtime change.
2. Keep scientific contracts separate from implementation fixes.
3. Add tests for lifecycle, hashing or result-schema changes.
4. Do not change evaluation thresholds after official results have been observed.
5. Never commit customer data, credentials, personal Drive identifiers or private outreach material.
6. Mark experimental claims as development evidence until an immutable result bundle exists.

## Contribution licensing

Unless a separate written agreement says otherwise, contributions intentionally submitted for inclusion in Akili Runtime must be compatible with the repository's PolyForm Noncommercial License 1.0.0 and may be incorporated into separately licensed commercial editions by the project owner. Open an issue before submitting a substantial contribution if these terms are not acceptable.
